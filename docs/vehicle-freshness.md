
# 차량 위치·ETA 최신성 및 연결 끊김 표시

마중 모바일 웹은 차량에서 전달받은 위치와 예상 도착 시간(ETA)의 최신성을 확인하여 탑승자에게 표시한다.

차량 위치가 일정 시간 갱신되지 않거나 휴대전화의 서버 연결이 끊긴 경우, 과거 정보를 현재 정보처럼 보여주지 않도록 처리한다.

이 문서는 기능 3.4의 차량 정보 최신성 표시, ETA 카운트다운, 연결 장애 처리 및 검증 결과를 설명한다.

> 차량 정보의 유효성은 백엔드 응답을 기준으로 판단한다. 웹은 휴대전화의 시스템 시계를 이용해 차량 정보의 수신 시각을 새로 추정하지 않는다.

백엔드 응답 필드 및 유효성 정책은 [차량 정보 최신성 API](https://github.com/majung-team/majung-backend/blob/main/docs/vehicle-state.md)를 따른다.

---

## 1. 주요 동작

| 상황 | 탑승자 화면 |
| --- | --- |
| 차량 정보 30초 이내 | ETA 카운트다운 및 차량 위치 정상 표시 |
| 차량 정보 30초 초과 | 마지막 ETA·차량 위치 흐림, 경과 시간 안내 |
| ETA 카운트다운 0초 | `곧 도착` 표시 |
| 차량 정보 2분 초과 | ETA 카운트다운 중단, 차량 위치 숨김 |
| 휴대전화 인터넷 끊김 | 서버 연결 안내, 이전 위치·ETA 숨김 |
| 서버 조회 실패 | 확인할 수 없는 차량 정보 숨김 |
| 차량 SDK 연결 해제 | `차량 정보를 기다리고 있어요` |
| 픽업 종료 | 기존 위치·ETA 표시 중단 |

30초와 2분은 서버 최신성 정책의 기본 기준이다.

웹은 서버가 제공하는 상태와 유효기간을 우선 적용한다.

---

## 2. 서버 응답 기반 최신성 판단

서버는 차량 정보가 수신된 시각과 SDK 원본 시각을 고려하여 최신성 정보를 제공한다.

### 주요 응답 필드

| 필드 | 의미 |
| --- | --- |
| `freshness` | 차량 정보 최신성 상태 |
| `durationSeconds` | 서버가 제공하는 ETA |
| `latitude` | 차량 위도 |
| `longitude` | 차량 경도 |
| `ageMillis` | 차량 정보 경과 시간 |
| `validForMillis` | 차량 정보의 남은 유효기간 |
| `sourceTime` | SDK 원본 정보 시각 |
| `receivedAt` | 서버 수신 시각 |
| `sequence` | 차량 정보 순서 식별 값 |

서버는 차량 정보의 경과 시간을 계산해 `ageMillis`로 전달한다.

웹은 해당 값을 기준으로 표시 상태를 결정한다.

### 최신성 상태

| 상태 | 의미 | 웹 처리 |
| --- | --- | --- |
| `FRESH` | 최근 수신한 유효한 차량 정보 | 정상 표시 |
| `STALE` | 갱신이 지연된 차량 정보 | 마지막 값으로 구분하여 표시 |
| `WAITING` | 현재 표시할 차량 정보 없음 | 대기 안내 |

`STALE`이라도 서버가 마지막 위치·ETA를 제공하는 동안에는 오래된 정보임을 명확히 표시한다.

서버가 좌표 또는 ETA를 `null`로 반환하면 이전 값을 복원해 표시하지 않는다.

---

## 3. 30초 이내 — 정상 표시

차량 정보가 최근 30초 이내의 유효한 정보인 경우 정상 상태로 표시한다.

### 표시 항목

- 차량 위치
- ETA 카운트다운
- 마지막 차량 정보 갱신 시각

차량 위치 마커는 정상적인 스타일로 표시한다.

ETA는 시간이 흐르는 동안 화면에서 1초 단위로 갱신한다.

정상 상태라는 이유만으로 별도의 차량 정보 조회 요청을 매초 전송하지 않는다.

---

## 4. 30초 초과 — 마지막 정보 표시

차량 정보의 경과 시간이 30초를 초과하면 `STALE` 상태로 표시한다.

### 화면 처리

- 차량 위치 흐림 처리
- 마지막 ETA 흐림 처리
- 마지막 갱신 경과 시간 표시
- 제공된 마지막 ETA 기준의 카운트다운 유지

안내 예시:

```text
마지막 갱신 35초 전
```

이 상태는 휴대전화가 서버에 연결되어 있지만 차량의 새로운 정보가 도착하지 않은 상황을 나타낸다.

마지막 값이 존재하더라도 실시간으로 확인된 차량 정보처럼 강조하지 않는다.

### 최신성과 연결 상태의 차이

`STALE`은 차량 데이터가 오래된 상태다.

휴대전화 자체가 인터넷에 연결되지 않은 `offline` 상태와는 구분한다.

---

## 5. 2분 초과 — 차량 정보 숨김

서버의 마지막 차량 정보 보관 기준을 초과하면 위치와 ETA를 표시하지 않는다.

기본 기준은 2분이다.

### 처리 방식

- ETA 카운트다운 중단
- 기존 차량 좌표 제거
- 지도 차량 마커 숨김
- 차량 위치 확인 중 안내 표시
- 마지막 갱신 경과 시간 표시

안내 예시:

```text
위치 확인 중 · 마지막 갱신 2분 전
```

서버에서 `durationSeconds`, `latitude`, `longitude`를 `null`로 반환하면 웹은 이전 정보를 유지하지 않는다.

시간이 지나도 최신 데이터가 없으면 차량이 움직이는 것처럼 가상의 위치를 계산하지 않는다.

### WAITING과의 구분

`WAITING`은 표시할 차량 정보가 없는 상태다.

차량 SDK의 명시적 연결 해제 등으로 `WAITING`이 되면 다음 안내를 사용한다.

```text
차량 정보를 기다리고 있어요
```

차량의 오래된 정보가 2분을 넘어 숨겨진 `STALE` 상태와 명시적인 `WAITING` 상태는 구분한다.

## 6. ETA 카운트다운

웹은 서버가 제공한 `durationSeconds`와 차량 정보의 경과 시간을 사용해 남은 시간을 표시한다.

### 계산 기준

- ETA 단위: 초
- 경과 시간 단위: 밀리초
- 남은 시간은 0초 아래로 내려가지 않음
- 휴대전화의 절대 시각을 기준으로 계산하지 않음
- 서버 응답 이후의 경과 시간은 브라우저의 단조 증가 시간으로 계산

`ageMillis`는 서버가 판단한 정보의 경과 시간이다.

웹은 응답을 받은 뒤 추가로 경과한 시간을 반영해 카운트다운을 진행한다.

다만 **`durationSeconds`가 SDK 원본 ETA인지, 서버에서 이미 경과 시간을 보정한 값인지에 따라 중복 차감 여부가 달라진다.**

따라서 구체적인 계산식은 실제 백엔드 응답 의미와 웹 구현을 기준으로 유지해야 한다.

같은 경과 시간을 두 번 차감하지 않는다.

### 카운트다운 0초

카운트다운이 0초에 도달하면 다음 문구를 표시한다.

```text
곧 도착
```

하지만 픽업 상태를 자동으로 `ARRIVED`로 변경하지 않는다.

ETA는 예상값이며 실제 차량 도착 이벤트가 아니다.

도착 여부는 서버의 픽업 상태를 기준으로 판단한다.

---

## 7. 화면 갱신

카운트다운과 경과 시간 안내는 1초마다 다시 계산한다.

### 갱신 원칙

1. 현재 표시할 차량 정보 확인
2. 서버 응답의 유효기간 확인
3. 화면에 필요한 값 계산
4. 이전 표시 내용과 비교
5. 실제 표시 내용이 바뀐 경우에만 갱신

1초마다 전체 화면을 무조건 새로 생성하지 않는다.

불필요한 DOM 갱신을 줄이고 사용자가 조작 중인 화면 상태를 유지한다.

### 적용 화면

동일한 최신성 처리 기준을 다음 화면에 적용한다.

- 초대 링크 픽업 화면(`/`)
- 로그인 계정의 진행 중 픽업 화면(`/account`)

두 화면에서 같은 차량 데이터가 서로 다른 최신성 기준으로 표시되지 않도록 한다.

## 8. SSE 및 상태 재조회

웹은 SSE를 이용해 서버의 변경 신호를 수신한다.

SSE 자체를 차량 위치의 최종 데이터로 사용하지 않는다.

### 기본 흐름

```text
차량 위치·ETA 변경
          │
          ▼
     백엔드 상태 저장
          │
          ▼
       SSE 변경 신호
          │
          ▼
       기존 API 재조회
          │
          ▼
    최신성·유효기간 확인
          │
          ▼
       화면 상태 반영
```

### 조회 정책

| 상황 | 동작 |
| --- | --- |
| SSE 변경 신호 수신 | 관련 API 재조회 |
| SSE 연결 정상 | 30초마다 보완 조회 |
| SSE 연결 실패 | 진행 중 픽업 3초 간격 조회 |
| 조회 중 추가 변경 발생 | 현재 조회 후 다시 조회 |
| 화면 숨김·로그아웃 | 불필요한 연결 정리 |

조회 중에 새 변경 신호가 도착했다면 현재 요청이 끝난 뒤에도 해당 변경을 확인한다.

기존 요청 완료만으로 아직 반영되지 않은 갱신 신호를 지우지 않는다.

[ETA 갱신 간격 및 SSE 검토](eta-updates.md)

## 9. 휴대전화 인터넷 연결 끊김

휴대전화가 인터넷에 연결되지 않으면 서버의 최신 차량 정보를 확인할 수 없다.

이 경우 마지막 위치와 ETA를 계속 표시하지 않는다.

### 연결 끊김 처리

브라우저에서 `offline` 이벤트를 수신하면 다음과 같이 처리한다.

1. 기존 SSE 스트림 종료
2. 차량 위치 숨김
3. ETA 카운트다운 숨김
4. 연결 상태 안내 표시
5. 기존 데이터를 현재 정보처럼 다시 표시하지 않음

안내 문구:

```text
인터넷 연결을 확인하세요
```

### 연결 복구

인터넷 연결이 복구되면 API로 최신 픽업 상태를 다시 조회한다.

새로운 응답을 확인하기 전까지 이전 차량 정보를 복원하지 않는다.

### 늦게 도착한 이전 응답 차단

인터넷 연결이 끊기기 전에 시작한 API 요청이 나중에 완료될 수 있다.

해당 응답이 뒤늦게 도착하더라도 이전 차량 위치와 ETA를 다시 표시하지 않는다.

연결 복구 이후 유효하게 조회한 데이터만 화면에 반영한다.

---

## 10. 서버 조회 실패

브라우저가 인터넷에 연결되어 있더라도 백엔드에 접근하지 못할 수 있다.

예를 들면 다음과 같다.

- API 서버 응답 실패
- 네트워크 요청 오류
- 요청 시간 초과
- 인증 또는 접근 권한 변경

최신 정보를 확인하지 못하는 동안 기존 위치·ETA를 현재 정보처럼 유지하지 않는다.

### 상태별 구분

| 상황 | 처리 |
| --- | --- |
| 차량 정보만 오래됨 | `STALE` 표시 |
| 차량 SDK가 명시적으로 정보 제거 | `WAITING` 표시 |
| 브라우저 offline | 인터넷 연결 안내 |
| API 조회 실패 | 서버 연결 오류 상태 안내 |
| 픽업 접근 권한 종료 | 기존 픽업 정보 숨김 |

연결 장애와 탑승자의 접근 권한 종료는 같은 상태로 취급하지 않는다.

---

## 11. 픽업 종료와 최신성

픽업이 완료·취소·만료되는 경우 차량 위치와 ETA를 더 이상 진행 중인 정보로 표시하지 않는다.

종료된 픽업에서 마지막으로 수신했던 차량 정보가 남아 있더라도 현재 위치로 복원하지 않는다.

### ETA와 픽업 상태

| 상황 | 결과 |
| --- | --- |
| ETA 0초 | `곧 도착` |
| 차량 도착 처리 | `ARRIVED` |
| 픽업 완료 | 종료 화면 |
| 픽업 취소 | 취소 상태 |
| 자동 만료 | `EXPIRED` |

ETA 카운트다운의 종료와 픽업 상태 전이는 분리한다.

---

## 12. 자동화 테스트

초기 차량 정보 최신성 표시 기능에서 다음 항목을 자동화 테스트로 확인했다.

### 경과 시간

- `ageMillis` 기반 경과 시간 계산
- 요청 왕복 시간 반영
- 휴대전화의 절대 시각에 의존하지 않음

### 표시 상태

- 30초 초과 시 흐림 처리
- 2분 초과 시 카운트다운 중단
- ETA 0초에서 `곧 도착` 표시
- 차량 정보가 없을 때 표시 제거
- offline 상태에서 위치·ETA 숨김
- 종료 상태에서 기존 정보 숨김

실행 명령:

```sh
npm test
```

정확한 테스트 통과 건수는 해당 실행 기록을 기준으로 확인한다.

## 13. 로컬 서버 연동 검증

로컬 서버에서 차량 정보의 경과 시간을 변경해 응답을 확인했다.

### 확인한 경계

| 서버 정보 경과 | 최신성 | 응답 |
| --- | --- | --- |
| 0초 | `FRESH` | 차량 좌표 및 ETA 제공 |
| 35초 | `STALE` | 마지막 차량 좌표 및 ETA 제공 |
| 125초 | `STALE` | 차량 좌표 및 ETA `null` |

### 확인 결과

서버의 최신성 상태와 마지막 값 제거 정책이 경과 시간에 따라 달라지는 것을 확인했다.

이 테스트는 서버 응답 검증이며 실제 휴대전화에서 시간이 흐르는 화면을 촬영한 시험은 아니다.

### 초기 배포 호환성

최초 구현 당시 서버의 신규 최신성 응답이 운영에 배포되기 전에는 `ageMillis`가 없는 응답이 존재할 수 있었다.

이 경우 웹은 기존 방식처럼 오래된 차량 정보를 숨기도록 처리했다.

이는 초기 배포 전환 시점의 호환성 기록이다.

---

## 14. 연결 복구 보완 — 2026년 10월 28일

초기 구현은 차량 정보의 경과 시간에 따라 화면을 구분하는 데 집중했다.

이후 서버 연결 실패와 브라우저 offline 상황에서도 이전 차량 정보가 다시 나타나지 않도록 보완했다.

관련 웹 PR:

- PR #39
- PR #41
- PR #45

### 보완 내용

- SSE 변경 신호 이후 API 재조회
- 서버 연결 실패 시 기존 차량 정보 숨김
- 브라우저 offline 이벤트 처리
- 차량 정보 유효기간 만료 처리
- 새 유효 응답 확인 후 정보 복원
- 연결 종료 이전 요청의 늦은 응답 차단

### 현재 적용 기준

차량 정보가 오래된 상태와 서버 연결 자체가 실패한 상태를 구분한다.

`STALE` 상태에서는 서버가 허용한 마지막 값을 표시할 수 있지만, `offline`이나 조회 실패로 최신 상태를 확인할 수 없으면 기존 정보를 숨긴다.

실제 휴대전화의 LTE 전환 및 장시간 재접속 검증은 별도로 남아 있다.

## 15. 검증 범위와 제한

### 확인한 범위

- 서버 `ageMillis` 기반 경과 시간 계산
- 30초 최신성 경계
- 2분 마지막 정보 제거
- ETA 0초 안내
- 초대 화면 및 계정 화면의 공통 표시 정책
- 서버 응답 기반 최신성 확인
- SSE 및 보완 조회
- 브라우저 offline 처리
- 늦은 응답 차단
- 종료 상태의 차량 정보 숨김

### 별도 검증이 필요한 범위

- 실제 휴대전화에서의 1초 카운트다운
- 실제 모바일 브라우저의 offline 이벤트 동작
- LTE·Wi-Fi 전환
- 장시간 네트워크 단절 및 복구
- 실차 SDK에서 전달되는 실제 ETA
- 브라우저·운영체제의 백그라운드 상태별 타이머 동작

로컬 자동 테스트와 서버 응답 검증 결과를 실제 휴대전화 또는 실차 검증 완료로 표현하지 않는다.
