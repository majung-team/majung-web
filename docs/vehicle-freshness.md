# 차량 정보 끊김 표시

기능: 3.4 끊김 표시. 서버의 `ageMillis`와 2분 이내 마지막 값을 사용한다. 서버 응답 형식은 [majung-backend 차량 정보 끊김 응답](https://github.com/majung-team/majung-backend/blob/main/docs/vehicle-state.md)을 따른다.

| 상황 | 탑승자 화면 |
| --- | --- |
| 마지막 수신 30초 이내 | 도착까지 남은 시간 카운트다운, 수신 시각, 차량 위치 |
| 30초 초과 | 남은 시간·위치를 흐리게 표시, "마지막 갱신 N초 전", 카운트다운 유지 |
| 카운트다운 0 | "곧 도착". 운전자가 도착을 알리기 전에는 도착으로 바꾸지 않음 |
| 2분 초과 | 카운트다운 정지, "위치 확인 중 · 마지막 갱신 N분 전" |
| 휴대전화가 서버에 못 닿음 | "인터넷 연결을 확인하세요". 지난 위치·시간 숨김 |
| SDK 연결 해제(`WAITING`) | 기존처럼 "차량 정보를 기다리고 있어요" |

- 경과 시간은 서버 값에 요청 왕복 시간을 더해 계산한다. 휴대전화 시계는 쓰지 않는다.
- 초대 링크 화면(`/`)과 계정 화면(`/account`)의 내 픽업 진행 중 항목에 같은 기준을 적용했다.
- 화면은 1초마다 다시 계산한다. 내용이 바뀐 경우에만 화면을 갱신한다.

## 확인 범위

- `npm test`: 경과 시간 계산, 30초 흐림·2분 정지, 0초에 "곧 도착", 정보 없음·오프라인·종료 시 미표시.
- 로컬 서버에서 응답이 0초 `FRESH`, 35초 `STALE`과 마지막 값, 125초 좌표·ETA null로 바뀌는 것을 확인했다.
- 실제 브라우저 화면 캡처, 실제 휴대전화·통신 단절 시험은 아직 하지 않았다.
- 서버 변경이 배포되기 전에는 `ageMillis`가 없으므로 기존처럼 지난 정보를 숨긴다.
