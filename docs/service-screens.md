# 웹 화면 사용 흐름

처음 접속하면 마중 시작 방법을 안내하고 카카오 로그인으로 이어진다. 받은 링크는 기존처럼 이번 픽업으로 바로 열린다.

로그인 후에는 세 화면을 사용한다.

- **픽업**: 받은 초대, 내가 보낸 요청, 픽업 대기와 현재 픽업을 확인한다. 진행 중인 픽업을 먼저 보여준다.
- **사람 찾기**: 운전자의 닉네임이나 마중 ID로 찾고 장소와 함께 요청한다. 연결 요청만 보낼 수도 있다.
- **내 정보**: 닉네임과 운전자 계정의 차량 연결을 관리한다.

현재 픽업에서는 운전자·만날 장소·도착 시간·지도를 먼저 보여주고 준비 상태를 바꿀 수 있다. 상태 수신 표시는 운전자의 읽음 여부와 구분한다. 새 장소는 제안과 차량 확정을 구분하고, 확정 전에는 기존 장소를 유지한다.

## 갱신과 연결 복구

SSE는 변경 신호만 보낸다. 신호가 오면 기존 API로 전체 상태를 다시 읽고 그 응답의 유효기간으로 위치와 시간을 표시한다. 서버에 이벤트 이력을 보관하지 않는다.

조회 중 새 변경 신호가 도착하면 다음 주기에 다시 읽는다. 이미 진행 중이던 조회가 끝났다고 신호를 지우지 않는다.

연결 실패·숨김·로그아웃 시 스트림을 정리한다. 실패하면 진행 중 픽업을 기존 3초 조회로 확인한다. SSE 연결 중에도 30초마다 상태를 다시 읽는다. 앱이 닫혀 있을 때 새 마중 요청을 푸시로 보내는 기능과는 별개다.

## 화면 검사

로컬 서버 실행 후 `http://127.0.0.1:4173/preview/account` 또는 `/preview/pickup`에서 390×844 화면을 확인할 수 있다. CSS 화면 크기를 검사하는 도구이며 실제 휴대전화·브라우저 시험을 대신하지 않는다.

실제 카카오 지도 SDK와 가상 로그인 계정으로 픽업 화면·SSE 연결·새 ETA 표시를 확인했다. `account-refresh.test.js`와 `stream.test.js`는 메뉴 이동, 갱신 신호, 기존 조회 방식 복구와 인증 헤더를 검증한다.
