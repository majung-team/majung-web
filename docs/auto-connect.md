
# 초대 링크 기반 탑승자 자동 연결

마중은 운전자가 공유한 초대 링크를 통해 탑승자가 별도의 이름 입력이나 운전자 승인 과정 없이 픽업에 참여할 수 있도록 지원한다.

탑승자가 초대 링크를 열고 **참여하기**를 선택하면 서버에서 연결을 처리하고, 정상적으로 연결된 경우 차량 위치·ETA 및 준비 상태 화면으로 이동한다.

단, **초대 링크에 접속한 것만으로 자동 참여하지는 않는다.** 사용자가 참여 버튼을 눌러야 실제 연결 요청을 전송한다.

이 문서는 기능 2.1의 탑승자 자동 연결, 일회용 초대 링크, 연결 해제 처리 및 검증 결과를 설명한다.

백엔드 API와 상태 전이 정책은 [자동 연결 및 탑승자 연결 해제](https://github.com/majung-team/majung-backend/blob/main/docs/auto-connect.md)를 따른다.

---

## 1. 주요 동작

| 항목 | 처리 |
| --- | --- |
| 참여 방식 | 초대 링크 + 참여하기 버튼 |
| 탑승자 이름 입력 | 필요 없음 |
| 운전자 개별 승인 | 필요 없음 |
| 초대 링크 사용 | 한 사람만 사용 가능 |
| 링크 열기만 한 경우 | 서버 참여 요청 없음 |
| 참여 완료 | 픽업 상태 및 준비 화면 표시 |
| 초대 재발급 | 이전 초대 링크 사용 불가 |
| 탑승자 연결 해제 | 기존 탑승자의 참여 권한 종료 |

이 기능은 초대 링크 기반 픽업에 적용한다.

로그인 계정으로 운전자를 검색하여 요청하는 마중 요청 대기열과는 별개의 흐름이다.

---

## 2. 탑승자 참여 흐름

### 사용자 절차

1. 운전자로부터 초대 링크 수신
2. 링크를 열어 픽업 참여 화면 확인
3. **참여하기** 버튼 선택
4. 서버에서 초대 코드 및 픽업 상태 검증
5. 연결 성공 시 픽업 화면 표시
6. 차량 위치·ETA 및 준비 상태 확인

이 과정에서 탑승자 이름을 별도로 입력하지 않는다.

초기 자동 연결에서는 기본 표시 이름인 `탑승자`를 사용한다.

### 처리 구조

```text
운전자
   │
   ▼
초대 링크 공유
   │
   ▼
탑승자가 링크 열기
   │
   ▼
참여 화면 표시
   │
   ▼
참여하기 버튼 선택
   │
   ▼
서버에서 초대 유효성 확인
   │
   ├── 유효하지 않음 → 참여 거절
   │
   └── 유효함
          │
          ▼
       탑승자 연결
          │
          ▼
     픽업 상태 ACTIVE
          │
          ▼
   위치·ETA·준비 상태 화면
```

---

## 3. 링크 접속과 참여 요청 분리

초대 링크를 열었다는 사실만으로 서버에서 탑승자 연결을 생성하지 않는다.

사용자가 명시적으로 **참여하기** 버튼을 선택해야 실제 연결 요청을 수행한다.

### 분리한 이유

메신저나 보안 서비스가 초대 링크를 미리 확인할 수 있기 때문이다.

예를 들면 다음과 같은 상황이 발생할 수 있다.

- 메신저의 링크 미리보기
- URL 안전성 검사
- 브라우저의 사전 로딩
- 링크 공유 서비스의 미리보기 요청

링크에 접근하는 것만으로 초대를 소비하면 실제 탑승자가 참여하기 전에 초대가 사용 완료될 수 있다.

따라서 **페이지 조회와 일회용 초대 소비를 분리**한다.

---

## 4. 일회용 초대 링크

초대 링크는 한 명의 탑승자만 사용할 수 있다.

### 사용 가능한 링크

유효한 링크를 통해 참여 요청을 보내면 서버가 탑승자를 연결한다.

### 이미 사용된 링크

다른 탑승자가 이미 사용한 링크로 참여를 시도하면 연결을 허용하지 않는다.

웹에는 다음 문구를 표시한다.

> 초대가 만료되었거나 이미 사용됐습니다

### 초대 재발급

운전자가 초대를 새로 발급하면 이전 링크는 더 이상 사용할 수 없다.

이전 링크를 보관한 사람이 새로운 탑승자로 연결되지 않도록 한다.

### 접근 권한

초대 링크의 사용 여부와 픽업 접근 권한은 서버에서 검증한다.

웹 화면에서 참여 버튼을 숨기는 것만으로 접근 권한을 통제하지 않는다.

---

## 5. 참여 완료 후 화면

탑승자 연결이 완료되면 서버의 픽업 상태를 조회하여 참여 화면을 갱신한다.

### 표시 정보

- 픽업 진행 상태
- 확정된 만남 장소
- 차량 위치
- 예상 도착 시간
- 탑승자 준비 상태

차량 위치·ETA는 서버에서 허용한 최신성 정책에 따라 표시한다.

오래된 정보를 실시간 위치처럼 표시하지 않으며, 위치 공유가 종료된 경우 기존 정보를 계속 보여주지 않는다.

[차량 정보 최신성](vehicle-freshness.md)

## 6. 탑승자 연결 해제

운전자는 연결된 탑승자를 해제할 수 있다.

실제 운전자 조작은 차량 앱에서 수행한다.

### 연결 해제 후 웹 처리

탑승자 화면은 다음 상태 조회에서 기존 참여 권한이 종료된 사실을 확인한다.

이후 참여 화면의 초기 상태로 돌아간다.

다음 안내 문구를 표시한다.

> 운전자가 연결을 끊었거나 초대가 다시 발급됐을 수 있어요

### 연결 해제 시 표시 정책

- 이전 픽업 참여 화면 종료
- 기존 차량 위치 숨김
- 기존 ETA 숨김
- 준비 상태 조작 중단
- 새로운 초대 링크를 통한 참여 안내

연결이 해제된 탑승자는 이전 접근 권한으로 차량 정보를 계속 확인할 수 없다.

---

## 7. 초대 재발급 후 다른 탑승자 연결

운전자가 기존 탑승자를 해제하고 새로운 초대를 발급할 수 있다.

### 처리 순서

1. 기존 탑승자 연결 종료
2. 기존 초대 링크 무효화
3. 새로운 초대 링크 생성
4. 다른 탑승자가 새 링크 열기
5. 참여하기 버튼 선택
6. 새로운 탑승자 연결

이전 탑승자의 브라우저는 다음 조회에서 연결 종료를 확인한다.

기존 링크를 통해 새 픽업 참여 권한을 획득할 수 없다.

---

## 8. 기존 승인 방식과의 호환성

과거에는 탑승자가 참여 요청을 보낸 뒤 운전자 승인을 기다리는 `WAITING_APPROVAL` 상태를 사용했다.

현재 신규 초대 참여에서는 해당 상태를 거치지 않는다.

### 현재 신규 참여

```text
초대 링크 → 참여하기 → ACTIVE
```

### 기존 데이터 호환

이전에 생성된 픽업 중 `WAITING_APPROVAL` 상태가 남아 있을 수 있으므로 기존 승인 화면 처리 코드는 유지한다.

이는 과거 상태를 처리하기 위한 호환성 코드다.

신규 자동 연결에서 운전자의 개별 승인이 필요하다는 뜻은 아니다.

---

## 9. 개발용 운전자 화면

로컬 개발 환경의 `운전자 확인 화면`에서는 탑승자 연결 상태를 확인할 수 있다.

개발 화면에는 다음 버튼을 제공한다.

```text
탑승자 끊기
```

이 버튼은 개발·시험을 위한 조작이다.

실제 운전자 서비스에서는 차량 앱에서 탑승자 연결을 해제한다.

개발용 웹 버튼을 일반 운전자의 실제 조작 화면으로 안내하지 않는다.

---

## 10. 로컬 통합 테스트

로컬 백엔드 서버와 헤드리스 Chrome을 이용해 초대 링크 참여 및 연결 해제 흐름을 확인했다.

### 시험 환경

- 로컬 마중 백엔드
- 헤드리스 Chrome
- 웹 초대 참여 화면
- 개발용 운전자 조작 화면

### 검증 순서

1. 탑승자가 초대 링크 열기
2. 이름 입력창이 없는지 확인
3. 참여하기 버튼 선택
4. 서버의 픽업 상태가 `ACTIVE`인지 확인
5. 기본 탑승자 이름이 `탑승자`인지 확인
6. 운전자가 탑승자 연결 해제
7. 탑승자 화면의 안내 문구 및 초기 화면 복귀 확인
8. 새로운 초대 링크 발급
9. 다른 탑승자의 참여 성공
10. 이전 초대 링크의 참여 거절 확인

### 검증 결과

| 항목 | 결과 |
| --- | --- |
| 이름 입력 없는 참여 | 확인 |
| 참여하기 이후 자동 연결 | 확인 |
| 서버 `ACTIVE` 상태 | 확인 |
| 기본 탑승자 이름 | `탑승자` |
| 운전자 연결 해제 후 화면 복귀 | 확인 |
| 새 초대로 다른 탑승자 참여 | 확인 |
| 기존 초대 링크 재사용 차단 | 확인 |

이 결과는 로컬 서버와 헤드리스 Chrome을 사용한 통합 시험 기준이다.

---

## 11. 검증 범위와 제한

### 확인한 범위

- 이름 입력 없는 참여 화면
- 명시적 참여 버튼
- 일회용 초대 링크 처리
- 참여 후 픽업 화면 이동
- 운전자 연결 해제 시 화면 복귀
- 새 링크를 통한 다른 탑승자 참여
- 이전 링크 재사용 차단
- 기존 승인 상태 화면 처리 유지

### 별도 검증이 필요한 범위

- 실제 휴대전화 브라우저
- 실제 메신저의 링크 미리보기 동작
- 모바일 네트워크 전환
- 실제 차량 앱에서의 탑승자 연결 해제
- 실차에서의 초대·참여 전체 흐름

로컬 브라우저 시험의 성공을 실제 휴대전화 또는 차량 연동 검증 완료로 기록하지 않는다.

## 문서 관리 기준

이 문서는 초대 링크 기반 탑승자 자동 연결과 연결 해제 이후의 화면 동작을 설명한다.

다음 항목을 구분하여 관리한다.

- 초대 링크 열기와 실제 참여 요청
- 초대 링크 사용 여부와 픽업 접근 권한
- 신규 자동 연결과 과거 승인 대기 상태
- 운전자 연결 해제와 초대 재발급
- 개발용 웹 조작과 실제 차량 앱 조작
- 로컬 브라우저 테스트와 실제 휴대전화·실차 검증

자동 연결 또는 초대 권한 정책을 변경하면 웹과 백엔드의 상태 처리 및 기존 픽업 호환성을 함께 확인한다.
