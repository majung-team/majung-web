# 내 연결 화면

상단 **내 연결**에서 카카오 로그인·닉네임 설정·사람 검색·연결 요청을 진행한다. 실제 카카오 인증정보는 서버에만 둔다. 브라우저는 HttpOnly 세션 쿠키를 사용하고, 변경 요청용 CSRF 토큰은 페이지 메모리에서만 보관한다.

## 사용하는 순서

1. 카카오로 로그인하고 마중에서 쓸 닉네임을 정한다.
2. **사람 찾기**에서 닉네임 또는 정확한 마중 ID를 검색한다.
3. 같은 닉네임이 있다면 마중 ID를 확인하고 **연결 요청**을 누른다.
4. 상대가 **받은 연결 요청**에서 수락하면 연결 목록에 **연결됨**으로 표시된다.
5. 보낸 요청은 취소할 수 있고 받은 요청은 거절할 수 있다. 연결된 상대는 확인 화면을 거쳐 연결 해제한다.

닉네임을 바꿔도 마중 ID와 기존 연결은 유지된다. 이 화면의 연결 승인으로 픽업이 생기거나 위치가 공개되지는 않는다. 사람 연결 이후 마중 요청·30분 만료·대기 순서와 차량 계정 연결은 아직 후속 작업이다.

## 오류가 나면

세션이 만료되면 다시 로그인한다. CSRF 검증 실패 시 세션 정보를 새로 받지만 변경 요청을 자동으로 다시 보내지 않는다. 통신 실패로 결과를 알 수 없으면 목록을 새로 확인한다. 인증 공급자 키나 프록시 HTML은 화면에 표시하지 않는다. 서버의 로그인이 꺼져 있으면 로그인 준비 안내를 표시하며 기존 픽업 초대는 그대로 사용할 수 있다.

## 확인한 범위 · 2026-10-25

- `npm test`: 기존 초대·위치 표시 6개와 계정 클라이언트 3개, 총 9개 통과
- 로컬 HTTP 공급자 + 실제 Spring Security·Tomcat·H2 서버 + 브라우저로 두 가상 계정의 로그인, 닉네임, 검색, 연결 요청·수락·해제 확인
- 보내는 쪽에는 확인 대기, 받는 쪽에는 수락·거절 버튼, 수락 후에는 연결됨 표시 확인
- 실제 카카오 사용자 로그인·실제 휴대전화·공개 서버의 계정 기능 배포는 이 시험에 포함하지 않음

아래 화면의 계정·닉네임·ID는 모두 로컬 시험에서 만든 가상 데이터다.

## 파일

| 파일 | 역할 |
| --- | --- |
| account.html, account.css | 내 연결 페이지와 화면 스타일 |
| account.js | 닉네임·검색·연결 상태 표시와 사용자 입력 처리 |
| account-api.js | 같은 주소의 서버 세션·CSRF 요청, 시간 제한·오류 처리 |
| account-api.test.js | 인증 요청 경계·재전송 금지·오류 처리 시험 |

서버의 로그인 후 이동 주소는 `/account.html`이다. 서버 저장소의 로그인 화면 이동 수정 PR과 함께 반영한다. 계정 세션은 기존 픽업의 Bearer 토큰을 대체하지 않는다.
