# 내 연결 화면

상단 **내 연결**에서 카카오 로그인·닉네임 설정·사람 검색·연결 요청을 진행한다. 실제 카카오 인증정보는 서버에만 둔다. 브라우저는 HttpOnly 세션 쿠키를 사용하고, 변경 요청용 CSRF 토큰은 페이지 메모리에서만 보관한다.

## 사용하는 순서

1. 카카오로 로그인하고 마중에서 쓸 닉네임을 정한다.
2. **사람 찾기**에서 닉네임 또는 정확한 마중 ID를 검색한다.
3. 같은 닉네임이 있다면 마중 ID를 확인하고 **연결 요청**을 누른다.
4. 상대가 **받은 연결 요청**에서 수락하면 연결 목록에 **연결됨**으로 표시된다.
5. 보낸 요청은 취소할 수 있고 받은 요청은 거절할 수 있다. 연결된 상대는 확인 화면을 거쳐 연결 해제한다.

닉네임을 바꿔도 마중 ID와 기존 연결은 유지된다. 이 화면의 연결 승인으로 픽업이 생기거나 위치가 공개되지는 않는다. 차량과 연결한 적 없는 탑승자도 검색 결과의 **마중 요청**에서 현재 위치·장소 설명을 보낼 수 있다. **연결만 요청**은 기존 사람 연결 기능이다. 운전자는 차량에서 마중 요청을 수락하며 이번 픽업의 대기 순서가 정해진다. 마중 요청 수락이 사람 연결 목록까지 자동 변경하지는 않는다.

## 오류가 나면

세션이 만료되면 다시 로그인한다. CSRF 검증 실패 시 세션 정보를 새로 받지만 변경 요청을 자동으로 다시 보내지 않는다. 통신 실패로 결과를 알 수 없으면 목록을 새로 확인한다. 인증 공급자 키나 프록시 HTML은 화면에 표시하지 않는다. 서버의 로그인이 꺼져 있으면 로그인 준비 안내를 표시하며 기존 픽업 초대는 그대로 사용할 수 있다. 아직 첫 세션 응답을 받지 못했을 때는 조회 중 안내를 표시한다. 첫 조회가 실패하면 오류와 다시 확인 버튼을 보여준다.

## 파일

| 파일 | 역할 |
| --- | --- |
| account.html, account.css | 내 연결 페이지와 화면 스타일 |
| account.js | 닉네임·검색·연결 상태 표시와 사용자 입력 처리 |
| account-api.js | 같은 주소의 서버 세션·CSRF 요청, 시간 제한·오류 처리 |
| account-api.test.js | 인증 요청 경계·재전송 금지·오류 처리 시험 |

서버의 로그인 후 이동 주소는 `/account`이다. 공개 HTTPS에서 해당 화면으로 이동하는 것을 확인했다. 계정 세션은 기존 픽업의 Bearer 토큰을 대체하지 않는다.


공개 계정 주소는 `/account`이며 HTML 파일명은 내부 구현이다. 기존 `/account.html`과 `/account/`는 쿼리를 유지해 `/account`로 이동한다. 로컬 개발 서버와 Caddy 모두 같은 규칙을 사용한다. 알 수 없는 페이지는 계정 화면으로 숨기지 않고 404를 반환한다.

2026-10-25 마중 전용 서버의 Caddy 설정을 검증하고 reload했다. 공개 `/account` 200, 기존 두 주소의 308 이동과 실패 쿼리 유지, CSS 200, 알 수 없는 주소·관리자 경로 404, API health 200을 확인했다. 정적 파일 교체와 Caddy 설정 변경은 별개이며, 이 규칙을 초기 서버 구성에도 유지한다.

## 새 탑승자의 마중 요청 · 2026-10-25 작업 브랜치

1. 카카오 로그인·닉네임 설정 후 운전자를 검색한다.
2. **마중 요청**에서 **현재 위치 선택**을 누르고 만날 장소를 설명한다. 기존 연결이나 차량 QR은 필요 없다. 위치 오차가 300m보다 크면 다시 선택하도록 안내한다.
3. 운전자 응답 전에는 30분 동안 대기한다. 수락되면 내 앞의 요청 수를 보여준다. 두 번째·세 번째 이후의 새 탑승자도 요청할 수 있다.
4. 내 차례가 시작되면 내 픽업의 ETA와 준비 상태를 보여준다. 대기 중 표시하는 ‘현재 진행 중인 픽업’ 시간은 내 장소 도착 예정 시간이 아니다.
5. 서버 정보 유효 시간이 지나면 ETA를 감춘다. 조회 중 같은 값이면 화면을 다시 만들지 않는다. 입력 중·탭을 숨긴 동안에는 주기 조회를 쉰다.

운전자 계정 연결은 차량 QR → 휴대전화 로그인·연결 요청 → 차량에서 본인 확인 후 승인 순서다. 계정 연결 QR은 5분 만료이며 주소 fragment를 바로 지운다. 로그인 복귀를 위해 같은 탭의 sessionStorage에만 잠시 보관한다. 탑승자에게 차량 권한을 저장하지 않는다.

이번 변경은 PR 검토 전 작업 브랜치 기준이다. 공개 서비스 배포 완료와 구분한다. 서버를 먼저 반영해야 새 웹 API를 사용할 수 있다. 마중 전용 DB에는 백업 후 추가 테이블 3개와 실행 계정 권한을 준비했다. 기존 앱은 재시작하지 않았다.

검증: 웹 자동 시험 10개, 실제 로컬 서버·브라우저에서 가상 탑승자B의 검색 → 현재 위치(가상 위치 주입) → 요청 → 수락 대기 → 자기 픽업 시작 → 준비 완료 확인. 다른 탑승자 이름·장소는 대기 화면에 표시되지 않았다. 새 위치의 약 2분 표시가 유효 시간 뒤 사라지는 것도 확인했다. 실제 휴대전화 GPS·실차 시험은 수행하지 않았다. 요청 수락·시작은 로컬 차량 권한 API로 전환했다.

![가상 계정으로 확인한 자기 픽업 진행](media/account-ride-active.png)

현재 위치 외 지도 검색·장소 선택과 앱이 닫혀 있을 때 알림은 아직 포함하지 않는다. 운전자별 열린 요청은 최대 50건이며 수락한 대기는 2시간 만료다.

계정 연결 QR로 같은 계정 페이지에 다시 들어오는 경우도 확인했다. 로그인 복귀 뒤 연결 요청이 유지됐고, 휴대전화 요청만으로는 내 차량 목록에 추가되지 않았다. 차량 권한 API의 승인 뒤 연결 완료가 표시됐다. 이 역시 가상 계정·로컬 서버 시험이다.
