# 마중 요청 장소 고르기

운전자를 검색해 ‘마중 요청’을 누른다. 장소명·주소로 검색하거나 지도·현재 GPS 위치에서 만날 지점을 고를 수 있다. 장소 설명에는 정문·주차장 입구처럼 서로 구분할 수 있는 내용을 적는다.

1. 장소명이나 주소를 검색하고 이름·주소를 확인해 결과를 선택한다. 직접 고르려면 지도를 이동해 만날 지점을 누른다. 또는 지도의 가운데를 맞추고 ‘지도 중심을 만날 장소로 선택’을 누른다.
2. 핀이 생긴 위치를 확인한다. 지도를 열기만 했을 때는 장소가 선택되지 않는다.
3. 만날 장소 설명을 적고 요청한다. 운전자가 장소를 확인하고 수락하면 픽업 대기에 들어간다.

GPS 권한은 현재 위치 선택을 눌렀을 때만 요청한다. 지도 핀 선택에는 GPS 권한이 필요 없다. GPS 위치는 2분이 지나면 다시 받아야 하며, 직접 고른 고정 지점은 같은 방식으로 만료시키지 않는다. 지도 로딩에 실패하면 기존 현재 위치 요청을 사용할 수 있다.

선택한 좌표와 설명만 기존 요청 API에 보낸다. 카카오 장소 ID를 내비에 넘기거나 경로를 계산하지 않는다. 진행 중인 픽업의 장소 변경 기능도 아니다. 사람이 안전하게 정차할 수 있는 장소인지 확인해야 한다.

## 검증

- 웹 자동 시험 36건: 지도 기본 중심점 자동 선택 방지, 명시적 클릭·중심 선택, 처리 중 변경 차단, 리스너 정리, 잘못된 좌표 거절, 실제 계정 요청 코드의 선택 좌표·설명 전송, 오래된 GPS 차단.
- 실제 카카오 SDK·로컬 가상 계정에서 핀과 설명 입력, 요청 버튼 활성화를 확인했다.
- 실제 휴대전화 GPS와 차량 SDK의 경로 반영은 별도 시험이다.

[카카오 공식 클릭·마커 예제](https://apis.map.kakao.com/web/sample/addMapClickEventWithMarker/)를 기준으로 지도 이벤트를 연결했다.

## 장소명·주소 검색

검색 결과는 한 번에 최대 10개(장소명 5개·주소 5개), 최대 3페이지다. 중복·좌표가 없는 항목은 제외한다. 자동으로 첫 결과를 선택하지 않는다. 결과를 누르면 지도가 이동하고 이름이 설명란에 들어간다. 필요하면 ‘정문 앞’처럼 설명을 보완한 뒤 별도 요청 버튼을 누른다.

검색은 버튼을 눌렀을 때만 수행한다. 타이핑할 때마다 호출하지 않는다. 검색어는 카카오에 전달되며 GPS 권한은 필요 없다. 결과 없음·일부 실패·8초 초과를 구분하고 지도·현재 위치 선택은 유지한다. 폼을 닫거나 다른 운전자에게 요청하면 늦은 검색 응답은 반영하지 않는다.

![검색 결과 — 가상 계정](media/pickup-place-search-results.png)

![검색으로 선택한 지점](media/pickup-place-search-selected.png)

SDK의 `services` 라이브러리를 사용한다. Caddy CSP의 `connect-src`에 `https://dapi.kakao.com`만 추가했다. 이 주소가 빠지면 지도는 보여도 검색은 실패한다. 로컬 HTTP 시험은 CDN의 프로토콜 상대 주소 때문에 별도로 HTTPS 업그레이드를 적용했으며 운영 HTTPS 정책 자체를 느슨하게 바꾸지는 않았다.

웹 시험 41건과 실제 카카오 장소명·도로명 주소 검색을 통과했다. 운영과 같은 허용 호스트 조건의 브라우저에서도 검색·선택·핀 이동·설명 자동 입력을 확인했다. 실차와 실제 휴대전화 GPS 시험과는 구분한다.
