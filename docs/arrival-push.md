# 도착 임박 웹 푸시

기능: 7.1 도착 임박 푸시. 차량이 약 3분 안에 도착하면 브라우저 알림을 한 번 보낸다. 서버 동작과 키 설정은 [majung-backend 도착 임박 웹 푸시](https://github.com/majung-team/majung-backend/blob/main/docs/arrival-push.md)를 따른다.

## 화면

- 위치 공유 중(`ACTIVE`)인 탑승자 화면에 **도착 3분 전 알림** 카드가 나온다. 초대 링크 화면(`/`)과 로그인한 `/account`의 진행 중 항목 모두 같다.
- **도착 알림 받기**를 누르면 브라우저가 알림 권한을 묻고, 허용하면 구독 주소를 서버에 보낸다. **알림 끄기**를 누르면 서버 구독과 브라우저 구독을 지운다.
- 서버에 VAPID 키가 없으면(`/api/v1/config`의 `webPushPublicKey`가 `null`) 카드를 보여주지 않는다.
- 도착(`ARRIVED`) 이후와 종료 후에는 카드를 보여주지 않는다.

| 상태 | 카드 |
| --- | --- |
| 알림 꺼짐 | 설명과 **도착 알림 받기** |
| 알림 켜짐 | "도착 약 3분 전에 알림을 보낼게요. 알림은 한 번만 보내요." 와 **알림 끄기** |
| 권한 차단 | 브라우저 설정에서 허용하라는 안내 |
| iPhone 브라우저 탭 | 홈 화면에 추가한 앱에서만 받을 수 있다는 안내 |
| 지원 안 함 | 화면을 열어 두면 안에서 확인할 수 있다는 안내 |

## 파일

| 파일 | 역할 |
| --- | --- |
| `sw.js` | 푸시를 받으면 "마중 · 차량이 약 3분 안에 도착해요" 알림을 띄운다. 푸시에 내용이 없어 문구는 여기 고정되어 있다. 알림을 누르면 열린 창으로 가고, 없으면 `/account`를 연다 |
| `push.js` | 브라우저 지원·권한 판정, 카드 표시, 구독과 해제 |
| `manifest.webmanifest` | 홈 화면에 추가할 수 있게 하는 정보. iPhone 웹 푸시의 조건이다. 아이콘은 아직 없다 |

## 알려진 제한

- iPhone은 Safari 탭에서는 웹 푸시를 받을 수 없다. 홈 화면에 추가한 앱에서 열어야 하고, 그 앱의 저장소는 Safari 탭과 분리되어 있다. 그래서 iPhone에서는 로그인한 `/account` 흐름만 쓸 수 있고, QR 초대 링크로 들어온 화면은 받을 수 없다.
- "링크만 열면 잠금 화면 알림까지 보장"되지 않는다. 브라우저·운영체제의 절전, 알림 설정에 따라 늦거나 오지 않을 수 있다.
- 알림은 한 번만 보낸다. 보낸 뒤에 구독을 다시 해도 다시 보내지 않고, 전송이 실패해도 재시도하지 않는다.
- 같은 브라우저에서 여러 픽업을 이어서 쓰면 구독 주소는 공유되지만 서버는 픽업마다 따로 기억한다. 새 픽업에서는 다시 **도착 알림 받기**를 눌러야 한다.

## 배포 전 준비

1. 서버: VAPID 키 설정, `arrival_push` 테이블 적용([서버 문서](https://github.com/majung-team/majung-backend/blob/main/docs/arrival-push.md)).
2. 서버 배포 스크립트(`deploy/release.py`)의 웹 파일 목록에 `push.js`, `sw.js`, `manifest.webmanifest`를 추가했다. 설치된 `/usr/local/sbin/majung-deploy`를 갱신하기 전에 웹을 배포하면 알 수 없는 파일로 거절된다.
3. Caddy CSP는 바꾸지 않아도 된다. 서비스 워커와 매니페스트는 같은 주소의 파일이다.

## 확인 범위

- `npm test`: 상태 판정, 카드 표시와 이스케이프, 키 변환, iPhone 판별, 서비스 워커의 알림 표시·클릭 처리, 계정 클라이언트의 새 경로와 CSRF.
- 로컬 서버(테스트용 VAPID 키)와 헤드리스 Chrome으로 실제 FCM까지 확인했다. 운영 Caddy와 같은 CSP를 붙인 주소에서도 같았다: 카드 표시 → 알림 허용 → `fcm.googleapis.com` 구독 → ETA 400 때는 알림 없음 → ETA 120에서 알림 수신 → 알림 끄기.
- Firefox, Safari, iPhone 홈 화면 앱, 실제 휴대전화와 운영 서버의 키로 받아 본 결과는 없다.

## 운영 반영 · 2026-10-26

웹 main `6dbf515`, 서버 main `c07462e`가 공개 서버에 반영됐다. `arrival_push` 테이블·실행 계정 권한과 설치된 배포 스크립트의 웹 파일 목록을 적용했다. VAPID 키는 서버에서 생성해 root 전용 환경 파일(0600)에 저장했다. 개인 키는 저장소·웹·차량 앱으로 전달하지 않는다.

공개 `/api/v1/config`에 공개 키가 내려오고, `/sw.js`, `/push.js`, `/manifest.webmanifest`가 200으로 응답하는 것을 확인했다. 키 적용 후 서버 health는 UP이다. 실제 휴대전화의 구독·알림 수신까지 확인한 결과는 아직 없다.

카카오맵은 전용 앱의 무료 쿼터 이관 대기 중이다. 기존 HANMAP의 지도 설정은 OFF 상태로 확인했다. [카카오 이관 요청](https://devtalk.kakao.com/t/topic/152375)을 게시했으며, 마중 지도 활성화·키 연결·지도 브랜치 main 반영은 이관 후 진행한다. 유료 월렛은 연결하지 않았다.

운영 Chrome의 가상 시험 픽업에서 알림 권한 허용 → 구독 → 알림 끄기까지 확인했다. 서버에 시험 ETA 400초·120초를 전달했지만 OS 배너 표시를 직접 확인하지 못했으므로 실제 수신 완료로 기록하지 않는다. 시험 픽업은 취소하고 시험 차량 권한은 철회했다. 실제 휴대전화의 수신 확인은 남아 있다.
