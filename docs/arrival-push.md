# 도착 알림 사용과 확인

진행 중인 픽업에서 ‘도착 전·차량 도착 알림’을 켜면 브라우저 권한을 요청한다. 도착 약 3분 전과 서버가 실제 도착 상태로 바뀔 때 각각 한 번 발송을 시도한다. 알림은 네트워크·OS 조건에 따라 늦거나 표시되지 않을 수 있다. 도착 시간 0초를 실제 도착으로 판단하지 않는다.

## 화면에서 확인하는 방법

도착하면 초대 링크 화면과 로그인 화면 모두 상단에 도착 안내와 약속 장소를 표시한다. 메시지를 입력하거나 다른 메뉴를 보고 있어도 안내는 갱신한다. ‘만날 장소 확인’으로 해당 픽업을 열 수 있다. 차량에서 탑승을 확인해 완료하기 전에는 공유 상태가 유지된다.

알림을 누르면 해당 픽업의 기존 탭을 먼저 찾는다. 로그인 참여는 요청 ID를 포함한 내 요청 화면을 연다. 초대 참여는 같은 픽업 ID의 기존 탭을 우선 열며, 새 탭에 참여 정보가 없으면 기존 탭 또는 초대 링크로 돌아가는 방법을 안내한다. 알림 URL에는 인증 토큰을 넣지 않는다.

## 브라우저 조건

- iPhone은 홈 화면에 추가한 웹앱에서 알림을 허용해야 한다. 일반 브라우저 탭과 다르다.
- 차단된 권한은 브라우저 설정에서 다시 허용해야 한다.
- 같은 브라우저의 구독을 여러 픽업이 사용할 수 있다. 한 픽업의 알림을 꺼도 브라우저 전체 구독을 해제하지 않는다.
- 새 웹은 이미 허용한 구독의 암호화 정보를 권한 창 없이 서버에 다시 등록한다. 등록에 실패하면 알림 토글로 명시적으로 재시도할 수 있다.
- 새 서비스 워커는 기존 알림 처리 코드를 갱신한다. 오래된 알림과 허용하지 않은 외부 경로는 제한한다.

## 저장하는 정보

서버에 endpoint·p256dh·auth를 보낸다. 브라우저가 발급한 값이며 로그인 비밀번호가 아니다. 원문을 문서나 로그에 남기지 않는다. 이름·좌표·초대 토큰 없이 알림 종류·공개 픽업 ID·서비스 내부 경로·발송 시각만 Web Push 표준으로 암호화한다.

종료·취소·권한 해제 때 서버 구독을 정리한다. 외부 푸시 서비스에 이미 전달한 알림은 회수할 수 없다. 자세한 서버 정책과 마이그레이션은 [백엔드 알림 안내](https://github.com/majung-team/majung-backend/blob/main/docs/arrival-push.md)를 따른다.

## 확인한 범위

서비스 워커 자동 시험에서 도착 전/실제 도착 구분, 올바른 픽업 경로, 다른 탭을 빼앗지 않는 동작, 오래된 알림과 외부 URL 차단을 확인했다. iPhone·Android 휴대전화의 새 실제 도착 푸시 수신은 별도 실기기 확인이 필요하다.
